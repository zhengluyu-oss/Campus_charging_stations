## Context

校园充电桩平台含 Vue 3 用户端（`frontend`）与管理端（`admin-frontend`），后端 API 不变。既往「清爽化」降低了特效负担，但毕业设计/面试 Demo 需要更强的第一眼辨识度。已确认方向：**科技能源感 + 方案 C 全站沉浸**（电影感动效 A、轻氛围 B、数据可视化 C），覆盖两端，不含鸿蒙。必须兼顾服务器部署与低配/投影场景的可读性与可降级性。

## Goals / Non-Goals

**Goals:**

- 两端统一 Campus Energy 视觉语言，用户端偏产品沉浸，管理端偏指挥舱。
- 按 L3/L2/L1 铺开 A/B/C 表现力；演示主路径与管理仪表盘达到旗舰观感。
- 提供 `effectsLevel: off | low | full` 与 `prefers-reduced-motion` 支持，保证可上线。
- 保留既有业务路由与 API，聚焦壳层、主题、组件皮肤、动效与图表。

**Non-Goals:**

- 不改后端接口、数据库、权限模型。
- 不改造 `harmonyos/`。
- 不恢复全站 MediaPipe 手势追踪或不可控的重粒子常驻方案。
- 不重写表格业务逻辑；管理端沿用现有 UI 库时仅换主题与容器。

## Decisions

### D1. 方案强度：全站沉浸（C），分阶段交付

- **选择**：视觉与能力按方案 C 设计；实施按 P0（演示路径+仪表盘）→ P1（其余 L2）→ P2（L1 与性能扫尾）。
- **理由**：满足「一眼惊艳」目标，又用阶段降低一次性翻车风险。
- **备选**：仅演示路径（A）或设计系统半重构（B）——已由用户否决。

### D2. 设计 Token 与字体

- **选择**：深空近黑底（`--bg-void`）+ 电光青/能量绿语义色；展示字体用于标题与数据，正文用高可读无衬线；玻璃面板低模糊细描边。
- **理由**：题材匹配「能源/充电」，避免廉价全屏发光。
- **备选**：浅色校园风、纯 Element 默认主题——冲击力不足。

### D3. 氛围层实现

- **选择**：App 根级单例 `AmbientCanvas`；默认 2D Canvas；仅欢迎/充电监控/管理仪表盘等 L3 评估轻量 WebGL；按路由切换强度预设，避免每页新建上下文。
- **理由**：方案 C 需要氛围，但单例 + 降级才能部署。
- **备选**：每页独立 Three 场景、或全站 MediaPipe——性能与稳定性差。

### D4. 动效实现

- **选择**：CSS transition/keyframes + 少量组合式封装（入场、CountUp、路由 cross-fade）；可选轻量 Vue 动效工具，不引入重型动画引擎。
- **理由**：可控、易降级、包体积小。
- **备选**：全程 GSAP/Lottie 堆叠——维护与性能成本高。

### D5. 可视化栈

- **选择**：统一 ECharts（若项目已有其他图表库则沿用并套能源主题）；封装 `TrendLine`、`StatusRing`、`HeatStrip`、仪表盘栅格等；主题从 CSS Token 映射。
- **理由**：答辩/面试数据叙事强，主题一致即可形成品牌。
- **备选**：纯 CSS 假数据装饰——不可复用且难讲真实性。

### D6. 特效运行时

- **选择**：`EffectsProvider` 管理等级；启动探测弱设备/移动端/`prefers-reduced-motion`；设置页可覆盖并写入 `localStorage`。
- **理由**：毕业设计可写「自适应体验」；面试可演示开关；线上可排障。
- **备选**：强制 full——低配与现场投影风险高。

### D7. 与旧特效关系

- **选择**：移除或替换残留手势追踪/重 Three 粒子为新氛围运行时。
- **理由**：与可控沉浸目标冲突。
- **备选**：并存两套——体积与复杂度翻倍。

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 全站沉浸导致卡顿/发热 | 三级 effects、L1 降密、单例氛围、异步分包 |
| 管理端表格投影不清 | L1/L2 保证对比度与字号；装饰弱于数据 |
| 包体积膨胀 | ECharts 按需、氛围 chunk 异步、字体子集或 CDN 策略 |
| 范围失控拖垮答辩档期 | 严格 P0→P1→P2；P0 即可演示 |
| 风格重回「花哨廉价」 | 禁止持续闪字/彩虹边框；能量色只做点缀 |
| 两端实现漂移 | 同源 Token 命名与组件契约文档化 |

## Migration Plan

1. **P0**：两端引入 `tokens.css` + `EffectsProvider` + 单例氛围；打满用户演示主路径（欢迎→地图→充电→订单）与管理仪表盘 L3。
2. **P1**：其余 L2 业务页皮肤与图表。
3. **P2**：L1 统一、性能与无障碍扫尾、生产构建验证。
4. **回滚**：特效默认改为 `low/off` 或回退主题 CSS 变量即可快速降噪；业务逻辑无迁移。
5. **部署**：验证 Nginx/静态资源缓存；确认特效开关在生产可用。

## Open Questions

- 地图底图供应商与热力图层是否已有现成封装（实施时以仓库现状为准）。
- 展示字体最终选型（Orbitron / Chakra Petch 等）与中文字体组合，需在 P0 定一版并两端锁定。
- 若管理端 Element Plus 主题覆盖成本过高，是否接受「外层 Glass 壳 + 内表轻度覆写」折中（默认接受）。
