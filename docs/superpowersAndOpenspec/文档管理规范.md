# 文档管理规范

> 所有 Superpowers 与 OpenSpec 产出必须遵守本规范。禁止在规范外随意创建文件或目录。

---

## 一、目录总览

```
项目根目录/
├── superpowers/                    # Superpowers 产出（思考、计划、执行侧主文档）
│   ├── project/                    # 项目长期知识（接手项目）
│   ├── audit/                      # 代码审计产出
│   └── changes/                    # 单次代码变更（AI 文档）
│       ├── <序号>-<变更名>/
│       └── archive/<序号>-<变更名>-YYYY-MM-DD/  # 已完成变更归档（日期在末尾）
│
├── openspec/changes/               # OpenSpec 变更账本（记录与追溯）
│   ├── <序号>-<变更名>/
│   └── archive/YYYY-MM-DD-<序号>-<变更名>/
```

### Git 策略（AI 文档）

**所有 AI 文档均不放入 `.gitignore`**，包括但不限于：

| 路径 | 说明 |
|------|------|
| `superpowers/project/` | 接手项目长期知识 |
| `superpowers/audit/` | 代码审计产出 |
| `superpowers/changes/` | 单次变更（含 `archive/`） |
| `openspec/changes/` | OpenSpec 变更账本（含 `archive/`） |

**逐任务功能代码提交时**：只 `git add` 本任务涉及的功能代码，**不要**把 AI 文档混入该次 commit；AI 文档是否单独提交、何时提交，由用户决定。

**禁止**：将上述 AI 文档路径加入 `.gitignore`。

## 二、命名规则

### 变更名 `<变更名>`

- 格式：**`<序号>-<简短描述>`**（序号在前，用连字符分隔）
- 序号：从 1 开始全局递增，不重复，归档后保留不回收
- 描述部分：**kebab-case**（小写英文 + 连字符），简短描述本次变更
- 示例：`1-add-user-auth`、`2-fix-login-timeout`、`3-optimize-query-performance`
- Bug 修复示例：`4-fix-issue-42`、`5-fix-login-crash`
- 禁止：中文、空格、日期前缀、无意义名称（如 `update`、`fix`）

### 文件命名

| 规则 | 说明 |
|------|------|
| 固定文件名 | `project/`、`audit/` 下使用规范规定的固定文件名，禁止自创 |
| 变更目录 | 一次变更一个目录 `superpowers/changes/<序号>-<变更名>/`，禁止用日期散落文件 |
| 禁止重复 | 同一内容不得同时在 `superpowers/` 和 `openspec/` 各写一份完整版 |

## 三、各目录职责与文件清单

### 3.1 `superpowers/project/` — 项目长期知识

**用途：** 接手项目时建立，供后续开发参考。无代码变更，不创建 OpenSpec 记录。

**固定文件（必须全部存在才算完成，共 6 个；文档不设字数上限，以详尽为准）：**

| 文件 | 内容 |
|------|------|
| `overview.md` | 技术栈（含版本）、完整目录树、本地启动手册、环境变量、规模粗估 |
| `architecture.md` | 分层架构、端到端请求链路、鉴权、横切关注点、架构风险 |
| `modules.md` | **逐业务域**展开：Controller / Service / Mapper / 前端入口 / 依赖 |
| `business-flow.md` | **逐流程**展开：步骤、状态机、异常分支、时序图 |
| `api-system.md` | **全量接口清单**（逐条：参数、响应、调用链、权限） |
| `infrastructure.md` | **数据库逐表逐字段**（对照 `docs/数据库*.md` / schema.sql / Entity）+ 连接池、缓存、部署、构建、端口 |

详细模板与自检清单见 [流程-01-接手新项目.md](流程-01-接手新项目.md)。

---

### 3.2 `superpowers/audit/` — 代码审计产出

**用途：** 全项目审计报告。无代码变更，不创建 OpenSpec 记录。

**固定文件：**

| 文件 | 内容 |
|------|------|
| `strategy.md` | 审计范围、优先级、路线图 |
| `code-quality.md` | 代码质量与架构问题 |
| `security.md` | 安全漏洞与权限风险 |
| `performance.md` | 性能瓶颈 |
| `dependencies.md` | 依赖风险与技术债 |
| `report.md` | 综合报告（P0–P3 排序 + 修复路线图） |

---

### 3.3 `superpowers/changes/<序号>-<变更名>/` — 单次变更（执行侧主文档）

**用途：** 本次变更的**唯一设计真相**与**唯一执行依据**。Superpowers 读写此目录。

**Git：** 本目录及下方归档目录均为 AI 工作流产出，**不放入 `.gitignore`**。逐任务提交功能代码时不要混入 AI 文档；AI 文档是否入库由用户决定。

| 文件 | 技能产出 | 角色 |
|------|---------|------|
| `design.md` | `brainstorming` | **设计主文档**（需求、方案、验收标准） |
| `plan.md` | `writing-plans` | **执行主文档**（逐步任务、代码、测试命令） |
| `review.md` | `requesting-code-review` | **质量路径复审报告** |
| `fix-plan.md` | `receiving-code-review` / `writing-plans` | **复审问题修复计划**（如有） |
| `diagnosis.md` | `systematic-debugging` | **仅 Bug 修复**：根因分析（现象、复现、根因、修复方向） |

规则：
- 新功能 / 重构质量路径：必须有 `design.md` + `plan.md`，完成前必须有 `review.md`
- Bug 修复：必须有 `diagnosis.md` + `plan.md`，完成前必须有 `review.md`（简单 Bug 可省略 `design.md`）
- **执行时只读 `plan.md`**，不另找其他计划文件

---

### 3.4 `superpowers/changes/archive/<序号>-<变更名>-YYYY-MM-DD/`

**用途：** Superpowers 质量路径已完成变更的只读归档。归档后不再作为执行依据，只用于追溯设计、计划、审查和修复记录。

**命名：** 与进行中目录使用相同基础名 `<序号>-<变更名>`，仅在末尾追加 `-YYYY-MM-DD`（归档日）。禁止 `YYYY-MM-DD-<序号>-<变更名>` 等日期前缀格式。

---

### 3.5 `openspec/changes/<序号>-<变更名>/` — 变更账本（记录与追溯）

**用途：** 记录轻量变更「为什么改、改了什么、是否完成」。OpenSpec 管理轻量路径生命周期与归档。

**Git：** 本目录及 `archive/` 均为 AI 产出，**不放入 `.gitignore`**。逐任务提交功能代码时不要混入 AI 文档。

| 文件 | 来源 | 角色 |
|------|------|------|
| `proposal.md` | `/opsx:propose` | 变更动机、范围、影响 |
| `tasks.md` | `/opsx:propose` | **轻量路径执行清单**（执行时打钩） |
| `specs/` | 按需 | 规格增量（影响对外能力时创建） |

规则：
- 流程 02（Superpowers 质量开发）和 Bug 修复（流程 03）不创建 OpenSpec 账本，避免第二套设计、任务和归档
- 轻量流程（流程 05，`/opsx:apply`）以 `tasks.md` 为唯一执行依据，不创建 `superpowers/changes/`

---

### 3.6 `openspec/changes/archive/YYYY-MM-DD-<序号>-<变更名>/`

**用途：** 已完成变更的只读归档。由 `/opsx:archive` 移动生成，日期为归档日。

---

## 四、主从关系（避免重复）

```
质量路径：superpowers/changes/<序号>-<变更名>/design.md
       → superpowers/changes/<序号>-<变更名>/plan.md
       → subagent-driven-development / executing-plans
       → superpowers/changes/archive/<序号>-<变更名>-YYYY-MM-DD/

Bug 修复：superpowers/changes/<序号>-fix-<简短描述>/diagnosis.md
       → superpowers/changes/<序号>-fix-<简短描述>/plan.md
       → TDD 修复 + code review + verification
       → superpowers/changes/archive/<序号>-fix-<简短描述>-YYYY-MM-DD/

轻量路径：openspec/changes/<序号>-<变更名>/proposal.md
       → openspec/changes/<序号>-<变更名>/tasks.md
       → /opsx:apply
       → openspec/changes/archive/YYYY-MM-DD-<序号>-<变更名>/
```

## 五、场景与目录对照

| 场景 | superpowers | openspec | 是否归档 |
|------|-------------|----------|---------|
| 接手项目 | `project/` | 不使用 | — |
| 代码审计 | `audit/` | 不使用 | — |
| 新功能（Superpowers 质量） | `changes/<序号>-<变更名>/` | 不使用 | Superpowers 归档 |
| 新功能（OpenSpec 轻量） | 不使用 | `changes/<序号>-<变更名>/` | `/opsx:archive` |
| Bug 修复 | `changes/<序号>-fix-<简短描述>/` | 不使用 | Superpowers 归档 |
