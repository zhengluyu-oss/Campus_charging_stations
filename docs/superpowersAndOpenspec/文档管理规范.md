# 文档管理规范

> 所有 Superpowers 与 OpenSpec 产出必须遵守本规范。禁止在规范外随意创建文件或目录。

---

## 一、目录总览

```
项目根目录/
├── superpowers/                    # Superpowers 产出（思考、计划、执行侧主文档）
│   ├── project/                    # 项目长期知识（接手项目）
│   ├── audit/                      # 代码审计产出
│   └── changes/<序号>-<变更名>/    # 单次代码变更（按变更名分目录）
│
├── openspec/changes/               # OpenSpec 变更账本（记录与追溯）
│   ├── <序号>-<变更名>/
│   └── archive/YYYY-MM-DD-<序号>-<变更名>/
```

---

## 二、命名规则

### 变更名 `<变更名>`

- 格式：**`<序号>-<简短描述>`**（序号在前，用连字符分隔）
- 序号：从 1 开始全局递增，不重复，归档后保留不回收
- 描述部分：**kebab-case**（小写英文 + 连字符），简短描述本次变更
- 示例：`1-add-user-auth`、`2-fix-login-timeout`、`3-optimize-query-performance`
- Bug 修复示例：`4-fix-issue-42`、`5-fix-login-crash`
- 禁止：中文、空格、日期前缀、无意义名称（如 `update`、`fix`）

### 文件命名

| 规则 | 说明 |
|------|------|
| 固定文件名 | `project/`、`audit/` 下使用规范规定的固定文件名，禁止自创 |
| 变更目录 | 一次变更一个目录 `superpowers/changes/<序号>-<变更名>/`，禁止用日期散落文件 |
| 禁止重复 | 同一内容不得同时在 `superpowers/` 和 `openspec/` 各写一份完整版 |

## 三、各目录职责与文件清单

### 3.1 `superpowers/project/` — 项目长期知识

**用途：** 接手项目时建立，供后续开发参考。无代码变更，不创建 OpenSpec 记录。

**固定文件（必须全部存在才算完成）：**

| 文件 | 内容 |
|------|------|
| `overview.md` | 技术栈、规模、目录结构、启动方式 |
| `architecture.md` | 分层架构、模块依赖、调用链路 |
| `modules.md` | 各模块职责、核心文件、依赖关系 |
| `business-flow.md` | 核心业务流程、状态流转 |
| `api-system.md` | 接口分类、权限体系、错误处理 |
| `infrastructure.md` | 数据库、缓存、MQ、部署架构 |

---

### 3.2 `superpowers/audit/` — 代码审计产出

**用途：** 全项目审计报告。无代码变更，不创建 OpenSpec 记录。

**固定文件：**

| 文件 | 内容 |
|------|------|
| `strategy.md` | 审计范围、优先级、路线图 |
| `code-quality.md` | 代码质量与架构问题 |
| `security.md` | 安全漏洞与权限风险 |
| `performance.md` | 性能瓶颈 |
| `dependencies.md` | 依赖风险与技术债 |
| `report.md` | 综合报告（P0–P3 排序 + 修复路线图） |

---

### 3.3 `superpowers/changes/<序号>-<变更名>/` — 单次变更（执行侧主文档）

**用途：** 本次变更的**唯一设计真相**与**唯一执行依据**。Superpowers 读写此目录。

| 文件 | 技能产出 | 角色 |
|------|---------|------|
| `design.md` | `brainstorming` | **设计主文档**（需求、方案、验收标准） |
| `plan.md` | `writing-plans` | **执行主文档**（逐步任务、代码、测试命令） |
| `diagnosis.md` | `systematic-debugging` | **仅 Bug 修复**：根因分析（现象、复现、根因、修复方向） |

规则：
- 新功能 / 重构：必须有 `design.md` + `plan.md`
- Bug 修复：必须有 `diagnosis.md` + `plan.md`（简单 Bug 可省略 `design.md`）
- **执行时只读 `plan.md`**，不另找其他计划文件

---

### 3.4 `openspec/changes/<序号>-<变更名>/` — 变更账本（记录与追溯）

**用途：** 记录「为什么改、改了什么、是否完成」。OpenSpec 管理生命周期与归档。

| 文件 | 来源 | 角色 |
|------|------|------|
| `proposal.md` | `/opsx:propose` | 变更动机、范围、影响（从 `design.md` 或 `diagnosis.md` 派生） |
| `tasks.md` | `/opsx:propose` + 与 `plan.md` 同步 | **勾选清单**（从 `plan.md` 提取任务项，执行时打钩） |
| `review.md` | `requesting-code-review` | 代码复审报告（完整质量流程必填） |
| `specs/` | 按需 | 规格增量（影响对外能力时创建） |

规则：
- **不在 OpenSpec 中维护第二份完整设计或计划**；`proposal.md` 是摘要，`tasks.md` 与 `plan.md` 对齐
- 轻量流程（`/opsx:apply`）无 `superpowers/changes/` 时，`tasks.md` 即为执行依据

---

### 3.5 `openspec/changes/archive/YYYY-MM-DD-<序号>-<变更名>/`

**用途：** 已完成变更的只读归档。由 `/opsx:archive` 移动生成，日期为归档日。

---

## 四、主从关系（避免重复）

```
superpowers/changes/<序号>-<变更名>/design.md  ──派生──▶  openspec/.../proposal.md
superpowers/changes/<序号>-<变更名>/plan.md      ──派生──▶  openspec/.../tasks.md
                                              执行时同步打钩 ◀──┘

执行依据（质量路径）：superpowers/.../plan.md  →  subagent-driven-development
执行依据（轻量路径）：openspec/.../tasks.md    →  /opsx:apply
```

---

## 五、场景与目录对照

| 场景 | superpowers | openspec | 是否归档 |
|------|-------------|----------|---------|
| 接手项目 | `project/` | 不使用 | — |
| 代码审计 | `audit/` | 不使用 | — |
| 新功能（质量路径） | `changes/<序号>-<变更名>/` | `changes/<序号>-<变更名>/` | `/opsx:archive` |
| 新功能（轻量路径） | 可选省略 | `changes/<序号>-<变更名>/` | `/opsx:archive` |
| Bug 修复 | `changes/<序号>-fix-<简短描述>/` | `changes/<序号>-fix-<简短描述>/` | `/opsx:archive` |
