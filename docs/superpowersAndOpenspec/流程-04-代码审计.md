# 流程 04：代码审计

**目标：** 全面扫描代码库，输出分级问题清单与可执行修复路线图。

**不使用 OpenSpec**（只有分析，无代码变更）。

发现的具体问题若需修复，每个修复作为独立变更，走 [流程 03：Bug 修复](流程-03-Bug修复.md)。

**前置：** 先阅读 [文档管理规范.md](文档管理规范.md)。

---

## 步骤 1：审计策略

**调用技能：** `brainstorming`（AI 自动）

描述目标："制定代码审计策略，不要修改任何代码。"

产出内容：审计范围与优先级、风险等级定义（Critical / High / Medium / Low）、审计路线图

**产出：**
```
superpowers/audit/strategy.md
```

---

## 步骤 2：代码质量审计

**调用技能：** `brainstorming`（AI 自动）

描述目标："进行代码质量审计。"

检查内容：分层设计与模块边界、循环依赖、重复代码、超长函数、命名规范、代码复杂度、测试覆盖率

**产出：**
```
superpowers/audit/code-quality.md
```

---

## 步骤 3：安全审计

**调用技能：** `brainstorming`（AI 自动）

描述目标："进行安全审计，重点检查认证授权、输入校验和敏感数据处理。"

检查内容：
- **身份与访问控制：** Token 验证、Session 安全、权限绕过、越权风险
- **输入输出安全：** SQL Injection、XSS、CSRF、Path Traversal、SSRF
- **数据保护：** 硬编码密钥、敏感数据暴露、日志泄露

**产出：**
```
superpowers/audit/security.md
```

---

## 步骤 4：性能审计

**调用技能：** `brainstorming`（AI 自动）

描述目标："进行性能审计。"

检查内容：SQL 性能与索引、N+1 查询、深分页、缓存策略、并发处理、内存占用

**产出：**
```
superpowers/audit/performance.md
```

---

## 步骤 5：依赖与技术债审计

**调用技能：** `brainstorming`（AI 自动）

描述目标："审计第三方依赖风险和技术债务。"

检查内容：第三方库版本与安全漏洞、过期依赖、技术债优先级与修复成本

**产出：**
```
superpowers/audit/dependencies.md
```

---

## 步骤 6：综合报告

**调用技能：** `brainstorming`（AI 自动）

描述目标："汇总所有审计结果，生成综合报告，按 P0–P3 排序并给出修复路线图。"

优先级定义：
- **P0（立即）：** 安全漏洞、数据泄露、系统崩溃
- **P1（优先）：** 严重性能瓶颈、核心业务风险
- **P2（计划）：** 代码质量问题、技术债
- **P3（记录）：** 轻微规范问题

**产出：**
```
superpowers/audit/report.md
```

---

## 步骤 7（可选）：具体 Bug 根因分析

若在审计中发现需要立刻确认的具体 Bug：

**调用技能：** `systematic-debugging`（AI 自动）

描述目标："对这个 Bug（描述现象）进行根本原因分析，不要修改代码。"

分析结果记录在对话中。如需修复，另起一个变更走 [流程 03](流程-03-Bug修复.md)。

---

## 完成标准

```
superpowers/audit/
├─ strategy.md
├─ code-quality.md
├─ security.md
├─ performance.md
├─ dependencies.md
└─ report.md
```

六个文件全部存在，审计阶段结束。
