# 流程 01：接手新项目，建立完整认知

**目标：** 在不改动任何代码的前提下，建立对项目架构、功能模块、数据模型、基础设施的**完整、可检索、可执行**认知。文档**不设字数上限**，宁可冗长也不要遗漏。

**不使用 OpenSpec**（此阶段只有分析，无代码变更）。

**前置：** 先阅读 [文档管理规范.md](文档管理规范.md)。

**核心原则：**
- **穷尽式采集**：能从代码、配置、数据库定义、注释、路由、接口注解中提取的信息，全部写入对应文档。
- **可验证**：每条关键结论标注信息来源（文件路径 + 行号或类名），便于后续核对。
- **按项目实际类型灵活适配**：纯前端项目不提数据库、CLI 工具不提 API 接口、库项目不提部署。**不存在的内容不硬写**。
- **禁止占位符**：不得出现「待补充」「TBD」「略」等未完成标记；确实无法确认时写「未在代码中找到，需人工确认」并说明已检索范围。

## 信息来源检索清单（开始前通读，按项目实际类型选取）

接手分析时，至少检索以下位置（**针对项目技术栈选取相关类别，不适用则跳过**）：

| 类别 | 典型路径 |
|------|----------|
| 项目配置文件 | `package.json`、`pom.xml`、`Cargo.toml`、`pyproject.toml`、`go.mod`、`CMakeLists.txt` 等 |
| 数据存储 | `schema.sql`、`db/migration/`、`prisma/schema.prisma`、`*.db`、`firestore.rules`、本地 JSON 文件等 |
| 代码入口 & 模块 | `src/`、`app/`、`main.py`、`main.ts`、`index.js`、`cmd/`、`lib/`、`bin/` |
| 接口定义 | `*Controller.java`、`routes/`、`api/`、`graphql/`、`*.proto`、OpenAPI 文档、`handler/` |
| 配置 | `.env.example`、`*.config.*`、`docker-compose.yml`、`application*.yml`、`settings.*` |
| 前端/UI | `router/`、`views/`、`pages/`、`components/`、`ui/` |
| 部署与运维 | `Dockerfile`、`docker-compose`、`nginx.conf`、`Makefile`、`Justfile`、`README` |
| 文档 | `docs/`、`wiki/`、`README` |

## 步骤 1：整体架构分析

**执行方式：** 按下方模板逐一填写（本步骤独立执行，无需调用 brainstorming）

**描述目标：**
> 帮我穷尽式分析这个项目的整体架构，不要修改任何代码。产出必须达到下方 `overview.md` 与 `architecture.md` 模板的每一项，不得省略。

### 1.1 产出：`superpowers/project/overview.md`

按以下章节**逐项填满**（无字数限制）：

#### 1. 项目基本信息
- 项目名称、仓库路径、一句话描述项目做什么、目标用户
- 项目成熟度判断（原型 / 迭代中 / 生产可用）及依据

#### 2. 技术栈全景（含版本号）
对每一项写明：**名称 + 版本 + 用途 + 配置文件来源**。按项目实际使用的技术填写，不存在的不写。

| 层级 | 可能包含的项（示例，非必填） |
|------|----------------------------|
| 语言与运行时 | JDK、Node.js、Python、Go、Rust 等 |
| 框架 | Spring Boot、Vue、React、Flask、Express 等 |
| 数据存储 | MySQL、PostgreSQL、Redis、MongoDB、SQLite、文件系统 等 |
| 构建工具 | Maven、npm、pnpm、Cargo、Webpack、Vite 等 |
| 其他 | Docker、消息队列、定时任务、WebSocket、文件上传 等 |

#### 3. 仓库目录结构（完整树形）
- 从项目根目录展开**至少 3 层**（关键子目录可更深）
- 每个**一级目录**附一句话职责说明
- 标注：前端代码、后端代码、公共模块、文档、脚本、配置文件

#### 4. 子项目 / 多模块说明
若有 monorepo 或多模块结构，逐模块说明：模块名、入口文件、启动方式、端口（如适用）、依赖关系。

#### 5. 本地启动手册（可逐步执行）
对每个可运行单元给出：
```text
前置条件（数据库已启动、环境变量等）
安装依赖命令
启动命令
访问地址（含端口，如适用）
默认账号（若有）
常见启动失败原因
```

#### 6. 环境变量与配置
- 列出 `.env.example` / 配置文件中**每一个**关键配置项
- 表格：配置键 | 默认值 | 含义 | 是否敏感 | 定义文件

#### 7. 外部依赖服务
- 数据库连接信息、第三方 API、SaaS 服务：是否接入、代码位置

#### 8. 规模与复杂度粗估
- 关键代码文件数、页面/组件数、数据表/集合数（按项目实际类型选取）
- 主要风险区域一句话列表（指向后续 `architecture.md` 展开）

#### 9. 文档与规范索引
- 项目内已有 `docs/`、`README` 清单及可信度说明
- 与 `superpowers/project/` 产出的关系（哪些是人工维护、哪些是 AI 接手产出）

---

### 1.2 产出：`superpowers/project/architecture.md`

按以下章节**逐项填满**（按项目实际类型裁剪）：

#### 1. 项目类型定位
（纯前端 / 前端+后端 / CLI 工具 / 库 / 游戏 / 数据管道 / 其他）

#### 2. 架构风格总览
- 整体模式（如适用：前后端分离 / 单体 / 微服务 / 插件式 / 事件驱动 等）
- ASCII 或 Mermaid 总览图（从输入/请求到最终输出的完整链路）

#### 3. 代码分层与模块组织
说明项目代码的组织方式，不必套用「Controller → Service → DAO」。对于不同项目类型，例如：
- 全栈项目：前端组件树、后端模块组织
- CLI 工具：命令入口、子命令、中间件链
- 库项目：对外暴露的 API、内部模块
- 纯前端：页面结构、组件层级、状态管理

#### 4. 请求/数据全链路（以一条典型操作为例）
逐步写出，每一步标注**具体文件名**：
```
用户操作 → 入口文件 → 核心处理函数 → 数据读写 → 结果返回
```

#### 5. 模块依赖关系
- 子模块 / 包之间的依赖关系
- 公共代码（工具类、通用组件、共享类型）集中存放位置

#### 6. 鉴权与安全架构（如适用）
- 登录流程、密码加密方式、Token 生成与校验
- 哪些接口免登录、哪些需角色（从拦截器/注解/配置归纳）
- Token 过期、刷新、登出策略

#### 7. 横切关注点（按项目实际列出）
- 异常/错误处理
- 日志记录
- 文件上传/存储
- 定时任务
- 其他跨模块功能

#### 8. 数据流与状态同步
- 数据在组件、服务、存储之间如何流动
- 是否有轮询、事件推送、定时修正

#### 9. 已知架构风险与技术债
逐条列出：现象 | 影响 | 相关文件 | 严重度（高/中/低）

#### 10. 扩展点说明
- 新增一个功能模块应放在哪、参考哪个现有模块
- 新增/修改数据实体应改哪些文件

### 2.2 产出：`superpowers/project/business-flow.md`

#### 每个核心流程必须包含

对项目的**每个核心功能流程**逐一展开，**按项目实际业务流程填写，不应照搬模板示例**。

## 完成标准

以下 **6 个文件全部存在**，且每个文件均达到上文模板的章节要求（无占位符、无「略」）：

```
superpowers/project/
├─ overview.md          # 步骤 1.1 — 项目全景与启动手册
├─ architecture.md      # 步骤 1.2 — 架构设计
├─ modules.md           # 步骤 2.1 — 逐模块类与文件对照
├─ business-flow.md     # 步骤 2.2 — 核心流程
├─ api-system.md        # 步骤 2.3 — 接口清单（按项目类型适配）
└─ infrastructure.md    # 步骤 3.1 — 数据模型 + 基础设施
```

### 自检清单（接手结束前逐项打勾）

- [ ] `overview.md` 含完整目录树、启动命令、配置项表
- [ ] `architecture.md` 含至少一条端到端请求/数据链路
- [ ] `modules.md` 覆盖项目的所有功能模块
- [ ] `business-flow.md` 每个核心流程有步骤编号
- [ ] `api-system.md` 接口数量与代码扫描结果一致（如适用）
- [ ] `infrastructure.md` 按项目实际内容填写，不存在的内容不硬写
- [ ] 全部结论均标注来源文件，无未解释的「待补充」
