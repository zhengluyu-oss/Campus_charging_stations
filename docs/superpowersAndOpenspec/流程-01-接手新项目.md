# 流程 01：接手新项目，建立完整认知

**目标：** 在不改动任何代码的前提下，建立对项目架构、模块、业务流程的完整认知。

**不使用 OpenSpec**（此阶段只有分析，无代码变更）。

**前置：** 先阅读 [文档管理规范.md](文档管理规范.md)。

---

## 步骤 1：整体架构分析

**调用技能：** `brainstorming`（AI 自动）

描述目标："帮我分析这个项目的整体架构，不要修改任何代码。"

分析内容：技术栈、目录结构、核心模块、主要依赖、分层架构、模块依赖关系、调用链路、风险区域

**产出：**
```
superpowers/project/overview.md
superpowers/project/architecture.md
```

---

## 步骤 2：业务模块与流程分析

**调用技能：** `brainstorming`（AI 自动）

描述目标："继续分析各个业务模块和核心业务流程。"

分析内容：各模块职责与核心文件、业务流程（用户/请求/数据）、状态流转、接口分类与权限体系

**产出：**
```
superpowers/project/modules.md
superpowers/project/business-flow.md
superpowers/project/api-system.md
```

---

## 步骤 3：数据与基础设施分析

**调用技能：** `brainstorming`（AI 自动）

描述目标："分析项目的数据库设计和基础设施。"

分析内容：核心表结构与表关系、索引设计、缓存策略、数据库 / Redis / MQ、部署架构

**产出：**
```
superpowers/project/infrastructure.md
```

---

## 步骤 4（可选）：深挖某个具体模块

**调用技能：** `openspec-explore`

```
/opsx:explore
```

进入只读探索模式，描述疑问。AI 追踪调用链、画 ASCII 架构图、比较方案，跟着你的思路走，无强制产出。

---

## 完成标准

```
superpowers/project/
├─ overview.md
├─ architecture.md
├─ modules.md
├─ business-flow.md
├─ api-system.md
└─ infrastructure.md
```

六个文件全部存在，接手阶段结束。
